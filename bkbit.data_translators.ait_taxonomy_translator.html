bkbit.data_translators.ait_taxonomy_translator module

AIT .h5ad -> Cell Taxonomy JSON-LD, driven by the model’s own annotations.

The point of this script is that it does not hardcode where fields live. Every slot in the cell_taxonomy model carries an ait_location annotation saying where its value comes from in an AIT .h5ad. linkml’s pydantic generator keeps those annotations, so they are read straight off bkbit.models.cell_taxonomy – no LinkML YAML needs to ship alongside the generated model.

Where a declared location cannot be honoured, the script may fall back to another source – but every such deviation is recorded in the report, never applied silently. That is the whole contract:

read from where the model says; if you cannot, say so.

Location grammar (as written in the sheet’s AIT Location column):

obs.<field> a column of obs obs.index the obs index obs.<annotation_level> template: one column per uns/hierarchy level uns.<key> a uns scalar uns.hierarchy (key|value) hierarchy keys (level names) or values (order) uns.cluster_info the whole cluster_info table uns.cluster_info.<pre>_<level> per-level wide column, needs un-pivoting obsm.X_<embedding> (key|value) an obsm embedding X / raw.X expression matrix groups (derived: <rule>) not stored; computed per <rule> (synthesized) minted identifier, no file source <path> (data only) present in files but NOT in the AIT schema

Reads only metadata groups over HTTP range requests; never materialises X.

curated_markers has range GeneAnnotation, so its values must be links. The file stores symbols; –gene_annotation (one gff2jsonld output, Turtle or JSON-LD, of the taxonomy’s species – checked) supplies the GeneAnnotation IRIs. Symbols that do not resolve are reported and left out, never written as strings – a bare string in an @id slot becomes a relative IRI against the output file’s path.

Usage:
python ait2jsonld.py URL_OR_PATH [–out out.jsonld] [–report rep.json]

[–species NAME] [–no-counts] [–gene_annotation ANNOTATION.ttl|.jsonld]

bkbit.data_translators.ait_taxonomy_translator.GENE_ANNOTATION_CLASS = 'https://identifiers.org/brain-bican/vocab/GeneAnnotation'

CellTypeTaxon.curated_markers has range GeneAnnotation, so the generated context types it "@type": "@id". The AIT file stores gene symbols (“PDGFRA, DCN”). Written as they are, a JSON-LD processor reads each symbol as a relative IRI and resolves it against the document’s base – the output file’s own path – so the graph ends up with file:///.../ACTA2: a node nothing else refers to. The value the model asks for is the IRI of a GeneAnnotation, which gff2jsonld mints. So symbols are looked up in the ONE gff2jsonld output the caller names for this h5ad, and a symbol that cannot be resolved is reported, never written as a string.

bkbit.data_translators.ait_taxonomy_translator.ONTOLOGY_PREDICATE = 'broad_match'

Which SKOS predicate the ontology terms are asserted with.

broad_match, not exact_match: the mapping is many-to-one. Measured across the HMBA files, up to three distinct CellTypeTaxon entries share one CL term (CL:0000128, CL:4042025, CL:0000192), and abbreviations reuse terms too. skos:exactMatch is symmetric and transitive, so asserting it three times against one term would entail that those three taxa are equivalent to each other, which is false – they are distinct taxa sharing a coarser class. skos:broadMatch says the true thing: the external concept is broader than ours.

bkbit.data_translators.ait_taxonomy_translator.ONTOLOGY_PREFIXES = frozenset({'CL', 'DHBA', 'UBERON'})

Prefixes whose terms are concepts in a published ontology, as opposed to records in a database.

The distinction decides which slot a value lands in. Biolink defines xref as a cross reference to a database identifier, and it serialises as a literal, so a CL or UBERON term sitting there joins with nothing. The SKOS mapping slots have a class range, so the generated context gives them "@type": "@id" and the CURIE becomes a real node that resolves against the published ontology. Database identifiers stay in xref, which is what it is for.

Keyed on the prefix rather than the table’s abbreviation_type column, because the two can disagree – the prefix is what decides whether a value is resolvable, and a row typed gene could still carry an ontology term. An unrecognised prefix is left in xref and reported, so a new ontology shows up as a deviation rather than silently becoming an unjoinable literal.

bkbit.data_translators.ait_taxonomy_translator.load_gene_annotation(path) → GeneIndex[source]

GeneIndex over one gff2jsonld output, in Turtle or JSON-LD.

The file’s species is the NCBITaxon:<n> xref of the OrganismTaxon its genes are in_taxon of – the same number the AIT file stores in organism_ontology_term_id, which build() checks it against. A file whose genes span several species is rejected: one h5ad, one annotation.

bkbit.data_translators.ait_taxonomy_translator.load_locations() → dict[source]

{(class, slot): {‘loc’:…, ‘sep’:…}} from the model’s annotations.

These come from the ait_location and ait_separator annotations on the cell_taxonomy LinkML schema. linkml’s pydantic generator preserves them verbatim under each field’s json_schema_extra["linkml_meta"], so the generated model is a complete source and the LinkML YAML does not have to ship alongside it. Verified equal to reading the schema with SchemaView: the same (class, slot) pairs with identical values.

The sheet also has Notes and Source columns, but both are deliberately mapped to ignore and so never reach the model; this used to read them and no longer does.

bkbit.data_translators.ait_taxonomy_translator.oid(cls_name: str, attrs: dict) → str[source]

Deterministic id, identical to every other bkbit translator.

Delegates to bkbit.utils.generate_bkbit_id.generate_object_id(), so the same entity minted here and by taxonomy2jsonld gets the same IRI. cls_name is accepted for call-site readability but is deliberately NOT hashed: including it would fork this translator’s ids away from the rest of bkbit. GeneAnnotation IRIs for the symbols that resolve; the rest go to tally.

With no gene index nothing is emitted: a symbol is not a valid value of a GeneAnnotation-ranged slot. A cell that is not a symbol list at all (e.g. “Six3 and Foxp1”) is not re-split – the declared separator is the only one – so it is reported unresolved for the data to be fixed upstream.

bkbit.data_translators.ait_taxonomy_translator.source_as_uri(path: str) → str | None[source]

The location the file was actually read from, as a URI.

An https URL pointing at S3 is rewritten to its s3:// form, so a taxonomy read over range requests records the same identifier the bucket owner would quote. Returns None for a local path – a filesystem location is not a permanent URL and must not be published as one.

{slot: callable} for slots the model constrains, e.g. with a pattern.

linkml’s pydantic generator compiles a pattern into a @field_validator rather than leaving it on the field, so it cannot be read off FieldInfo or the JSON schema.
